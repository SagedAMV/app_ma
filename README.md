## 🏗️ كيف تبني التطبيق وتشغله؟

1. **ثبّت Android Studio** (أحدث نسخة مستقرة).
2. افتح المشروع: `File → Open` واختر مجلد `Mahfazty-Kotlin`.

4. شغّل التطبيق على محاكي أو جهاز حقيقي (زر ▶).
5. لبناء ملف APK نهائي: `Build → Build Bundle(s) / APK(s) → Build APK(s)`.

> ⚠️ ملاحظة: يتطلب البناء **JDK 17** (يأتي مدمجاً مع Android Studio الحديثة).

## 🔒 القواعد المالية المنقولة حرفياً

1. لا يمكن أن يصبح أي صندوق (بنك/كاش) سالباً — ولا الإجمالي.
2. الادخار والأهداف **قيم مشتقة من العمليات** (لا مال من العدم): حذف عملية يعيد المال تلقائياً.
3. الصرف اليومي من الكاش افتراضياً، والدخل للبنك.
4. دين العميل لا يمكن أن يتجاوز "الرصيد الحقيقي" للحساب.
5. `goal_add / savings_add / client_fund` تُسجَّل كمصروف حقيقي من المحفظة — نفس نسخة الويب تماماً.

## 🧱 المعمارية (MVVM + Repository + Room)

```
app/src/main/java/com/mahfazty/smart/
├── MahfaztyApp.kt          ← حاوية التبعيات (Manual DI)
├── MainActivity.kt         ← الثيم + RTL + التنقل + الشريط السفلي
├── domain/                 ← منطق خالص 100% قابل للاختبار
│   ├── model/Models.kt     ←   النماذج والأخطاء (sealed)
│   ├── Categories.kt       ←   الفئات الافتراضية + المخصصة
│   ├── WalletEngine.kt     ←   محرك القواعد المالية (دوال نقية)
│   └── Formatters.kt       ←   التنسيق العربي + مولّد المعرفات
├── data/
│   ├── db/                 ← Room: 8 جداول + 7 واجهات DAO
│   └── Repositories.kt     ← 3 مستودعات (إعدادات/محفظة/عملاء)
└── ui/
    ├── theme/              ← ألوان نسخة الويب + وضع داكن
    ├── components/         ← مكونات مشتركة (بطاقات، مخططات، نوافذ)
    ├── screens/            ← 8 شاشات (6 تبويبات + تفاصيل عميل/حساب)
    ├── dialogs/            ← 15+ نافذة (عمليات، تحويل، أهداف، عملاء...)
    ├── viewmodels/         ← 9 نماذج عرض بحالة StateFlow
    └── util/Share.kt       ← مشاركة واتساب + ملفات
```

**تدفق البيانات (Unidirectional):** قاعدة البيانات ← Room Flow ← Repository ← ViewModel (StateFlow) ← Compose.

## 🎯 تطبيق المهارات العشرين في الكود الفعلي

| # | المهارة | مكانها في الكود |
|---|---|---|
| 1 | Null Safety | `?.let { return it }` في المستودعات — النمط `WalletError?` |
| 2 | `val` والثبات | كل النماذج `data class` بخواص `val` فقط |
| 3 | `data class` | `Transaction`, `Goal`, `Client`, `AppSettings`... |
| 4 | `when` الشامل + Smart Casts | `WalletEngine.bankBalance` وكل معالجات الأخطاء |
| 5 | `sealed interface` | `WalletError` بحالاته: `BoxShortage`, `TotalShortage`... |
| 6 | Extension Functions | `toDomain()`, `toEntity()`, `toInsufficient()`, `message()` |
| 7 | Scope Functions | `apply` في بناء النوايا، `let` في معالجة النتائج |
| 8 | Default/Named Arguments | كل نماذج `AppSettings`، وسائط الدوال المسماة |
| 9 | العمليات الوظيفية | `filter/map/sumOf/firstOrNull/groupBy` في المحرك |
| 10 | String Templates | `"$sign${Money.fmt(...)}"` ورسائل التطبيق |
| 11 | Coroutines + Structured Concurrency | `viewModelScope.launch` في كل ViewModel |
| 12 | حقن Dispatchers | Room يتولى الإزاحة تلقائياً — لا تجميد للواجهة |
| 13 | Flow + StateFlow | كل الحالة `stateIn(WhileSubscribed)` |
| 14 | عدم كشف المتغير | `_toast` خاص + `toast` للقراءة فقط |
| 15 | Delegated Properties | `by lazy` في الحاوية، `by remember` في الواجهة |
| 16 | MVVM + UDF | الأحداث ← ViewModel ← حالة ← شاشة |
| 17 | Repository | 3 مستودعات كطبقة وسيطة وحيدة |
| 18 | State Hoisting | كل الشاشات تستقبل `state + callbacks` بلا حالة داخلية |
| 19 | Side Effects | `LaunchedEffect` للتوست، `remember` للحالة المحلية |
| 20 | الأداء | `key` في القوائم، مشتقات محسوبة، حالة ثابتة |

## 🔄 ما تغيّر عن نسخة الويب (عن قصد)

1. **Room بدل localStorage** — بيانات أصلية دائمة وقابلة للاستعلام، مع نسخ احتياطي JSON متوافق.
2. **حذف سجل المعاملات يحرر مساحة** بدل تكديس نص JSON واحد.
3. **الوضع الليلي ثلاثي**: فاتح/داكن/حسب النظام (الويب: فاتح/داكن فقط).
4. **الأيقونات**: أيقونة تكيفية رسمية للمحفظة.
5. **الافتتاحية**: تفتح مباشرة — Compose أسرع من WebView فلا حاجة لتأخير مصطنع.
